# 删除任务与联动业务撤销

在 Bot 任务列表点击**批量删除**，可跨页勾选任务，也可删除符合当前搜索、Bot 和状态筛选条件的全部任务。删除前核对确认框中的数量。筛选删除采用任务快照，最多处理 10,000 条，每次请求最多 500 条。

排队任务会退出执行队列；正在推理的任务会中断，旧执行租约失效。已发出回调或回调结果未知的任务保留供核对，并在结果中报告为阻塞项。删除无法撤回已经发生的外部操作。

## 后端删除接口

使用有权调用目标 Bot 的 API Key，与提交任务时的认证方式一致：

```http
POST /api/v1/bots/BOT_CODE/tasks/delete
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "idempotencyKeys": ["business-task:INSTANCE_ID"]
}
```

每个值必须与提交该任务时的 `Idempotency-Key` 完全一致。数组要求 1–500 个不重复的非空值，每个值最多 256 个字符。删除范围限于该密钥所属用户及其授权 Bot，不会按标题或业务描述模糊删除。

响应示例：

```json
{
  "requested": 1,
  "deleted": 1,
  "alreadyDeleted": 0,
  "blocked": [],
  "interrupted": []
}
```

HTTP 200 也可能包含阻塞项。只有 `blocked` 为空且 `deleted + alreadyDeleted == requested` 时，才可确认全部完成。阻塞项返回对应提交键及原因，例如 `callbackInFlight`。相同请求可安全重试，包括请求成功但响应丢失的情况。

如果删除先于提交到达，系统会保留隐藏的去重记录；之后使用该提交键会返回 HTTP 409（`taskDeleted`），防止迟到投递重新创建已撤销的任务。任务正文及事件记录会删除，小型身份去重记录保留。

## 撤销后重新生成业务任务

每个实际业务任务实例使用新的提交键。`externalTaskId` 可继续作为业务关联字段，它不承担提交去重职责。

| 操作           | 提交键                 | 结果                                       |
| -------------- | ---------------------- | ------------------------------------------ |
| 创建实例 A     | `business-task:A`      | 创建 Bot 任务                              |
| 撤销 A         | 删除 `business-task:A` | 删除 A，或报告阻塞原因                     |
| A 的迟到重试   | `business-task:A`      | 删除完成后拒绝重建                         |
| 重新生成实例 B | `business-task:B`      | 即使 `externalTaskId` 相同，也能创建新任务 |

业务后端确认撤销状态后，应持久化撤销通知并通过可靠队列重试。通知需要覆盖后台和批量操作，不能仅由浏览器按钮触发。保留原 Bot 目标及提交键，确保删除准确对应原实例。回调结果不明确时进入核对流程，不能直接记为删除成功。

## 升级顺序

先升级 Panda，再升级调用后端及业务任务生命周期联动。删除接口复用现有 API Key 和存储，无需新增 Panda 环境变量或数据库迁移。尚未接入删除接口的调用方仍可按原方式提交任务。
