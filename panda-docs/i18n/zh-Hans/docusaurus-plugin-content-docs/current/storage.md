title: 状态、文件与备份
---

源码运行默认将应用状态保存在 `$HOME/.panda-force`，容器中为 `/var/lib/panda-force`。配置、日志及业务数据库与工作区分开；模型引擎保留自己的账户和会话状态。

输入框上传的本地文件保存在所选工作目录。未提交工作目录的旧客户端继续使用原持久暂存位置，默认是 `$CODEX_HOME/panda-force-uploads`，可通过 `PANDA_FORCE_ATTACHMENT_ROOT` 配置；已有链接继续可用。选择 SQLite 时，项目关联记录保存在应用状态目录的 `data/projects.sqlite`；使用 MySQL 时，业务记录使用所选数据库，文件和模型状态仍需分别备份。

## 附件工作目录

每个共享工作区使用以下布局：

```text
<working-directory>/attachments/
  input/<upload-id>/<original-filename>
  work/<session-id>/
  output/<session-id>/
```

上传开始时固定目标目录，之后切换页面不会改变未完成上传的位置。新建受管理项目使用服务端解析的工作区。输入文件保留原名，不同上传 ID 防止重名冲突；处理与交付目录按会话隔离。原件、中间文件与交付文件保留在工作区卷中，会话结束时不会自动删除。

每次提交、追加说明与排队消息都携带应用工作区信息，告诉引擎在哪里处理和交付文件。已有会话同样适用，不替换原指令或重启共享守护进程。该信息不显示为用户消息，不进入输入历史；普通工程改动仍保存在对应项目文件中。

引擎和 Web 服务必须通过**同一绝对路径**访问同一份持久存储。应用准备的 `attachments/.panda-attachments.json` 标记用于核对工作区；缺失或标识不符说明挂载不一致。服务无法准备可写附件目录时，普通对话仍可继续，但会明确告知附件工作区不可用。

容器私有目录、仅宿主可见的 `/mnt/data` 与 `/tmp` 不能直接作为交付位置，`sandbox:` 链接也不会改变挂载。外部工具生成的文件须先复制到工作区交付目录，再提供链接。下载与图片路由继续执行权限、路径及符号链接检查。

已有本地附件及 OSS 上传保留原路由。OSS 输入存储不会自动公开引擎生成的文件；交付文件仍需写入共享工作区。链接失败时，系统不会按文件名猜测或任意搜索宿主目录。

## 为创作原件配置 S3

安装管理员可以在**设置 → 存储**为新的图片、视频、幻灯片、网页及其他创作文件选择本地存储或 S3 兼容连接。选择文件类型，再配置 bucket、region、可选对象前缀与凭据。高级选项包括根 endpoint 和 path-style；endpoint 为空时使用区域 AWS S3 地址。服务商需支持应用使用的条件写入、元数据、确切版本与字节范围操作。

默认使用本地存储。保存配置不会联络服务商，也不会迁移已有文件；新写入会先检查读取权限与连接。修改连接后，已有原件保持其已保存位置；旧连接需要更换凭据时，使用对应的修复表单。凭据字段留空保留已保存值，离开页面清除新输入的敏感值。Secret Key 保留在服务端；签名 URL 包含非保密的 Access Key 标识与限于该对象的签名。连接需要读、写与清理权限，启用版本控制时还需要访问应用保存的对象版本。

查看、播放和下载先验证应用登录与项目权限，再将浏览器重定向到签名的确切对象 URL，由对象存储直接发送原件。链接最多复用 24 小时，临近过期时刷新；签名在本地计算，不需要另向 S3 申请 token。浏览器必须能够访问配置的 endpoint。本地文件保持原路由，画廊缩略图仍由应用生成并提供。应用不设置公开 ACL 或修改 bucket 策略；管理员自行配置的公开策略不受此流程改变。申请新链接仍需应用认证。

在查看器中选择**获取图片链接**或**获取文件链接**，可显示并复制直达 URL；此操作会提示有效期和实际到期时间。持有签名链接的人在到期前可以访问，即使之后退出登录、权限变化或文件移入回收站；这些操作阻止新的授权，但不撤销已发出的 URL。永久删除完成后，已知对象版本被清理，原链接不再获取原件。临时凭据或服务商策略可能使链接更早失效。

移入回收站保留原件及资源，便于恢复。**彻底删除**记录不可撤销请求，并排队清理该文件的已知 S3 版本与资源。独立副本使用不同对象 key。中断或拒绝的清理会保留状态，支持重启后重试；暂时查不到对象，不代表一次不确定的上传已被删除。

该配置独立于静态 CDN 和会话附件存储，只覆盖创作原件及其资源；模型原生日志与渲染恢复缓存保持原存储。备份时同时保留应用元数据、项目内容和 S3 对象，确保原件位置与清理回执可恢复。删除原件不会自动清除共享引擎状态。

配置、独立凭据记录与清理日志位于应用状态目录的 `original-storage` 子目录，标准 Compose 状态卷已持久化。需要自定义父目录时，设置 `PANDA_FORCE_ORIGINAL_STORAGE_PARENT` 并为该路径挂载持久存储；应用仍使用其中的专属 `original-storage` 子目录。这些能力已包含在公开的 0.1.10 应用镜像中。

## 受管理的项目目录

项目文件夹以项目 code 命名。`PANDA_FORCE_PROJECTS_ROOT` 的程序默认值是 `<PANDA_FORCE_HOME>/projects`；标准 Compose 设置为 `/home/codex/workspace/projects`，已包含在工作区卷中。`PANDA_FORCE_ALLOW_EXTERNAL_DIRECTORIES` 默认为 `true`；精确设置为 `false` 时，浏览器目录和会话可见范围限制在项目根目录。

根目录是**容器内路径**，需要卷或绑定挂载。共享宿主引擎要求两侧使用同一绝对路径；容器私有路径不会自动对宿主可见。设置自己的根目录时，准备匹配 UID/GID 和写入权限。已有未标记目录不会自动接管或覆盖。不同安装共用根目录时也共用项目文件夹名称空间，各自的业务数据库不会自动共享归属。

禁用外部目录后，浏览器目录与原生历史使用新的缓存范围；修改后重启并刷新。这是浏览器可见性策略，命令访问仍受引擎权限控制。应用附件保留授权路由，原生会话记录仍保存在引擎状态目录中。

## 数据卷与备份

Compose 服务名为 `panda-force`，正式镜像为 `hiforceai/panda-force:0.1.10`。标准命名卷是带项目名前缀的 `panda-force-state`、`panda-force-model-state` 与 `panda-force-workspace`。Grok 叠加配置另加账户卷和 socket 卷；账户卷由账户服务持有，socket 卷只保存通信状态，不能代替账户备份。

已有数据卷通过 `PANDA_FORCE_STATE_VOLUME_NAME`、`PANDA_FORCE_MODEL_VOLUME_NAME` 与 `PANDA_FORCE_WORKSPACE_VOLUME_NAME` 指定实际 Docker 名称。绝对宿主目录绑定使用 `PANDA_FORCE_HOME_HOST`、`PANDA_FORCE_MODEL_HOME_HOST` 与 `PANDA_FORCE_WORKSPACE_HOST`。修改默认名称不会迁移或删除旧数据；升级保持原项目名与卷名。

分别备份配置、业务数据库、模型状态、附件与工作区。SQLite 使用在线备份，或停止应用后复制完整数据目录，包括存在的 WAL/SHM 文件；MySQL 使用其数据库备份流程。`docker compose down` 停止服务；带 `--volumes` 会删除命名卷。Grok 账户通过原持有者管理，避免多份副本独立轮换同一 Refresh Token。

日志输出到 stdout/stderr 与滚动文件。日志保持私有，反馈问题前清除敏感内容。[升级指南](updates.md)说明保留卷和检查镜像的步骤。
