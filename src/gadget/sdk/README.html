PandaForce Gadget SDK

The workbench is a registered composition. System modules live in src/gadget/system. The host contains no component-ID or service-name dispatch. Installed extensions use the same manifest and backend service registry; their UI runs in a sandbox.

Build and install

bun run build:gadget-sdk
npm install /path/to/dist/panda-gadget-sdk-0.1.0.tgz

The SDK is built locally; this command does not publish to a registry. It exports client, server and frame entry points with TypeScript declarations. Review the example at examples/gadget/batch-summary.

Register a module

import { GadgetRegistry } from '@hiforceai/panda-gadget-sdk/server';
export function registerGadgets(registry) {
  registry.register({ manifest, frontend: bundledUi,
    services: { summary: {
      authorize: context => permissions.canRead(context.owner),
      handle: (context, input) => provider.summary(context.owner, context.config, context.signal)
    }}
  });
}

Set PANDA_FORCE_GADGET_MODULES to an administrator-owned JSON array of absolute module entry paths, for example ["/opt/panda/gadgets/batch-summary/server.js"], then restart. Server modules are trusted administrative code. UI is isolated, with network access and parent DOM access denied. The layout cannot nominate arbitrary script URLs.

Manifest

Declare a namespaced ID, API/config versions, four-locale titles and descriptions, singleton policy, desktop size constraints, schema-like bounded config fields, services, actions, refresh budget and optional default placement. Duplicate IDs and invalid registrations fail startup. A failed frontend or an unavailable package affects only its instance. Config migrations are registered by source version and preserve the original configuration on failure.

Frontend

import { defineGadget } from '@hiforceai/panda-gadget-sdk/frame';
defineGadget((root, initial) => ({
  async update(context) {
    const summary = await context.data('summary');
    if (context.signal.aborted) return;
    root.textContent = String(summary.total);
  },
  dispose() { root.replaceChildren(); }
}));

Bundle the frontend into one classic JavaScript entry, then provide its text as frontend. Use context.locale and context.theme, not application globals. Handle all four locales: en, zh-CN, zh-HK and zh-TW. Updates carry a new AbortSignal; release listeners, timers and observers in dispose. Do not start private polling loops; the host schedules visible widgets, coalesces reads and limits request concurrency.

HTTP client

import { GadgetClient } from '@hiforceai/panda-gadget-sdk/client';
const client = new GadgetClient(baseUrl, authenticatedFetch);
const catalog = await client.catalog();
const layout = await client.layout();
await client.save(layout, operationId); // retry identical input with this ID after an uncertain response
await client.invoke(gadgetId, instanceId, config, 'summary');

Browser calls use the existing same-origin authenticated session. Server integrations supply an authenticated fetch transport and the correct Origin header where required. The SDK introduces no universal API key or authentication bypass.

API

GET  /api/gadgets/catalog
GET  /api/gadgets/layout                 # private layout; ETag = revision
PUT  /api/gadgets/layout                 # If-Match + operationId + layout
POST /api/gadgets/data                   # registered service invocation
POST /api/gadgets/actions                # registered action invocation
GET  /api/gadgets/frontend/:gadgetId     # package-owned bundled UI

Data/actions reauthorize the current identity on every call. Input/output sizes and concurrency are bounded. Services must respect context.signal; business mutations must use their own durable idempotency protocol. The host does not automatically retry actions. Registered navigation results are limited to application routes. Credentials remain on the server.

Persistence and upgrades

Layouts and replay receipts use SQLite by default or the application's selected MySQL pool. The gadgets DDL module participates in the existing schema registry, inspection and application-wide migration. Saves use revisions and transactions, keep receipts across restart and never overwrite another user. Existing user layouts do not receive new default widgets automatically. Missing/disabled/incompatible instances preserve their position and configuration.

Acceptance

Check add/remove, singleton handling, drag/resize and keyboard controls, separate mobile order, save/cancel/undo/reset, uncertain replay and conflicts, owner isolation, revoked service access, schema migration, missing widgets and single-widget recovery. Review real PC/H5 rendering and language/theme updates. Do not use production records or engine tasks for development tests.
